# Event log schema (v1)

Each project records an append-only log at `projects/<name>/events.jsonl`, one JSON object per line. Do not edit the file by hand. Writers append under a file lock (`.events.lock`), so `seq` is unique and increases within a project.

```json
{
  "v": 1,
  "ts": "2026-10-14T06:50:36.956Z",
  "seq": 7,
  "actor": "api/implementer",
  "type": "file.edited",
  "target": "api",
  "payload": {
    "path": "src/a.ts",
    "kind": "edited",
    "lines": { "added": 2, "removed": 1 },
    "tool": "edit",
    "patch": "patches/7.patch"
  }
}
```

| Field     | Type            | Meaning                                                                                                                                                                                                                   |
| --------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v`       | `1`             | Schema version. Breaking changes increment it.                                                                                                                                                                            |
| `ts`      | ISO 8601 string | When the action happened (the hook timestamp when there is one).                                                                                                                                                          |
| `seq`     | integer         | Unique within the project, increasing from 1. Use it for ordering, because `ts` can tie.                                                                                                                                  |
| `actor`   | string          | Who acted: `coordinator`, `<child>/<role>` (e.g. `api/implementer`, `web:ui/tester`, `web/settings/tester`), `<repo>/repo-coordinator`, `ext:<name>`, `cli` or `user`. An unattributed child appears as `unknown/<role>`. |
| `type`    | string          | One of the types below. Consumers must ignore unknown types.                                                                                                                                                              |
| `target`  | string \| null  | The child id the event is about (`<repo>`, `<repo>:<package>` or `<repo>[:<package>]/<unit>`), or `null` for project-level events.                                                                                        |
| `payload` | object          | Type-specific data. When there is a patch, `payload.patch` is the path of the patch file relative to the project directory.                                                                                               |

Patches are stored in `patches/<seq>.patch` (gitignored) and are not inlined. Payloads, messages and patches pass through secret redaction: tokens, keys, credentials and private keys become `[REDACTED]`.

## Event types

| Type                                                  | Written by                 | Payload                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `project.created`                                     | CLI                        | `sessionId`, `host` (`copilot` \| `claude`)                                                                                                                                                                                                                                                                                      |
| `session.started` / `session.ended`                   | hook                       | `sessionId`, `source`, `host` (`copilot` \| `claude`) / `reason`                                                                                                                                                                                                                                                                 |
| `session.replaced`                                    | CLI                        | `previous`, `sessionId`, `reason: "missing"`. `resume` found that the host no longer has the recorded session, so it started a new one.                                                                                                                                                                                          |
| `agent.spawned`                                       | hook                       | `agentId`, `agentName`, `agentDisplayName`                                                                                                                                                                                                                                                                                       |
| `agent.stopped`                                       | hook                       | `agentId`, `agentName`, `response` (full text)                                                                                                                                                                                                                                                                                   |
| `message.sent`                                        | coordinator                | `from`, `to`, `text` (full message)                                                                                                                                                                                                                                                                                              |
| `file.added` / `file.edited` / `file.deleted`         | hook (postToolUse)         | `path` (relative to the worktree), `kind`, `lines.added`, `lines.removed`, `tool`, `patch` (cumulative diff of the file vs HEAD)                                                                                                                                                                                                 |
| `worktree.snapshot`                                   | hook (agent stop)          | `worktree`, `base`, `files[]` (`path`, `kind`, `added`, `removed`, `binary?`), `totals`, `patch`. Ground truth for the diff since the child's base commit. Skipped when nothing has changed since the last snapshot.                                                                                                             |
| `worktree.created` / `worktree.removed`               | CLI                        | `repo`, `repoPath`, `worktree`, `branch`, `base`, `baseSha`; `worktree.created` adds `copiedFiles[]` and `missingCopyFiles[]` (names only, never contents)                                                                                                                                                                       |
| `phase.changed`                                       | state updates              | `scope` (`project` \| `child`), `from`, `to`                                                                                                                                                                                                                                                                                     |
| `question.asked` / `question.answered`                | coordinator                | `id`, `from`, `text` / `id`, `answeredBy` (`spec` \| `coordinator`), `text`                                                                                                                                                                                                                                                      |
| `question.escalated`                                  | repo coordinator (helper)  | `question`, `repo`. Logged by `npx openfleet escalate <project> <child> --question`: a question that changes a cross-repo contract or the Shared approach. The child becomes `blocked` (`blockedReason: needs-escalation`) until the top coordinator runs `escalate --resolve`.                                                  |
| `assumption`                                          | coordinator                | `child`, `question`, `decision`, `rationale`, `contractChange` (bool). A decision the coordinator made without the user because the spec did not cover it. The run summary lists every assumption.                                                                                                                               |
| `contract.changed`                                    | coordinator                | `contract`, `affected[]`, `summary`                                                                                                                                                                                                                                                                                              |
| `spec.written` / `spec.approved`                      | coordinator                | `path`, `summary` / `changes` (the user's answer to the spec review question that ends the grill)                                                                                                                                                                                                                                |
| `plan.submitted` / `plan.validated` / `plan.rejected` | coordinator                | `plan`, `reasons[]`. `plan.rejected` adds `reason` (required): `invalid` (fails the spec), `inconsistent` (differs from the Shared approach or another plan; then `with[]` lists the other children) or `out-of-scope` (a greenfield plan implements a `## Follow-ups` item or adds endpoints, pages or tables nobody asked for) |
| `plans.consistent`                                    | coordinator (helper)       | `children[]`, `plans` (child → plan path), `gateOpen`. Logged by `npx openfleet gate <project> consistent` once the listed plans agree with the Shared approach and each other. A repo coordinator's sibling check (`gate <project> consistent --repo <repo>`) logs it too, with `repo` and actor `<repo>/repo-coordinator`.     |
| `baseline.passed`                                     | baseline (helper)          | `files[]` (baseline test files, relative to the worktree), `command`, `results`, `summary`. Logged by `npx openfleet baseline <project> <child> --report`; actor `<child>/baseline`.                                                                                                                                             |
| `test.run`                                            | tester (via helper)        | `command`, `exitCode`, `passed`, `summary`                                                                                                                                                                                                                                                                                       |
| `child.failed`                                        | coordinator                | `reason`, `retries`, `findings[]`, `worktree`, `blocked[]` (dependents now `blocked`). Logged when 3 retries and one coordinator-guided attempt all fail.                                                                                                                                                                        |
| `extension.ran`                                       | coordinator (helper)       | `extension`, `slot`, `status` (`done` \| `failed`), `summary`. Logged by `npx openfleet ext result`; `target` is the child for per-child slots.                                                                                                                                                                                  |
| `extension.skipped`                                   | coordinator (helper)       | `extension`, `agent`, `slot`, `reason`, `checked[]` (directories searched). Logged by `npx openfleet ext plan` when none of the entry's `when.files` exist.                                                                                                                                                                      |
| `extension.outputs`                                   | coordinator (helper)       | `extension`, `slot`, `outputs` (flat key → string), `followUps[]`. Stored in `state.json`; dependents get the outputs as "Upstream outputs". `outputs.prUrl` sets the child's `prUrl`.                                                                                                                                           |
| `extension.failed`                                    | coordinator (helper)       | `extension`, `slot`, `reason`, `attempts` (2), `blocked[]`. A blocking entry failed twice (or timed out). In a per-child slot the child is `failed` and a `child.failed` event follows; in `plans-ready` every active child is `blocked`.                                                                                        |
| `worktree.synced`                                     | coordinator (claim helper) | `onto` (integration branch), `sha`. A grouped child's branch was fast-forwarded to the integration branch tip when its implementer was claimed.                                                                                                                                                                                  |
| `preflight.passed`                                    | cli (preflight helper)     | `repos`, `checks` (count). Git can write ref locks and worktree admin dirs in every repo and the worktrees dir is writable.                                                                                                                                                                                                      |
| `preflight.failed`                                    | cli (preflight helper)     | `repos`, `failed` (`repo`, `check`, `path`, `code`), `hint`. `EPERM` gets the sandbox hint, `EACCES` a file-permissions hint. Greenfield projects add `toolchain` (on PATH, `ENOENT` with an install hint) and `registry` (reachable, `UNREACHABLE`) checks.                                                                     |
| `repo.created`                                        | cli (repo create helper)   | `key`, `path` (workspace-relative), `remote` (origin URL or null), `github` (`owner/name` or null). Logged by `npx openfleet repo create <key> --project <name>` for a greenfield repo: empty initial commit on `main`, registered in repos.json with `greenfield: true`.                                                        |
| `project.continued`                                   | cli (continue)             | `from` (the finished project), `repos[]` (reused, no longer greenfield), `followUps` (count seeded into the spec draft). Logged by `npx openfleet continue <project> [name]` on the new project.                                                                                                                                 |
| `stack.created`                                       | coordinator (stack helper) | `base` (default branch), `layers[]` (`child`, `branch`, `sha`; bottom first, the top layer is the integration branch). Logged by `npx openfleet stack <project> <repo>` before the layers are opened as GitHub stacked draft PRs.                                                                                                |
| `child.merged`                                        | repo coordinator (helper)  | `into` (integration branch), `branch`, `sha`. Logged by `npx openfleet merge`.                                                                                                                                                                                                                                                   |
| `merge.conflict`                                      | repo coordinator (helper)  | `into`, `files[]` (conflicting), `outside[]` (conflicting files the child does not own), `scopeViolation`. The child was rebased onto the integration branch and goes back to `planned` for its implementer to resolve.                                                                                                          |
| `run.completed`                                       | coordinator                | `mode` (`staged` \| `draft-pr`), `children`                                                                                                                                                                                                                                                                                      |

Hooks capture `file.*` events only for paths inside a child worktree. File writes by shell commands are not visible to tool hooks; `worktree.snapshot` covers them.

**Copied local files** (a repo's `copyFiles`, for example `.env.local`) never reach the log: `file.*` events for them carry `copiedFile: true` and no `patch`, `worktree.snapshot` leaves them out of `files` and `patch`, and every event payload and patch is also scrubbed of the values found in those files (env, YAML and JSON style `key = value` lines; values shorter than 6 characters, booleans and numbers are left alone) before it is written.

## Run report

`npx openfleet report` reads this log to draw the run: child-scoped `phase.changed` for the timeline, `agent.spawned`/`agent.stopped` (matched by `agentId`) for agents at once, `plan.submitted`/`plan.validated`/`plan.rejected`/`plans.consistent` for the plan gate, the last `worktree.snapshot` per child for lines changed, `test.run` for tests, `assumption` for decisions, and `session.started`/`session.replaced` for the host session ids whose transcripts hold token usage. See [design.md](design.md#run-report).

## Attribution

- **Spawns.** Before spawning a planner, baseline, implementer, tester or repo coordinator, the coordinator runs `npx openfleet claim <project> <child> <role>`. Under a workspace lock it sets `pendingSpawn: <role>` and `claimedAt` on the child, allows at most one unconsumed claim per role across the workspace and enforces the workspace `maxParallel` (`openfleet.json`, default 6); otherwise it returns `wait`. The `subagentStart` hook consumes the oldest claim for the spawned agent's role, records the role, and injects the child's assignment (worktree, branch, spec, contracts) into the subagent's prompt. Claims older than 5 minutes are ignored. When the hook consumes a claim it also records the agent's id on the child (`agentIds.<role>`), so that agent's later tool calls and its stop are attributed by id, even with many planners running in parallel. As a fallback for agents with a shell, `npx openfleet ack <project> <child> <role>` re-prints the assignment, and the `postToolUse` hook binds the agent's id if it was not recorded yet. A stop with no recorded id falls back to matching the unique child with that role (see **Stops**).
- **File changes.** The hook maps the absolute file path to the child whose worktree contains it (longest match), then takes the role from the agent id recorded on that child (when the call carries one), else from the child's current `role` or phase.
- **Extension agents.** `openfleet-ext-*` agents are attributed to their extension (`ext:<name>`) through `core/extensions.json`.
- **Upstream outputs.** When it injects a planner, baseline, implementer or tester assignment, the `subagentStart` hook also adds an "Upstream outputs" table with every extension output recorded on the children this child depends on, directly or transitively. Planners run before the `plans-ready` gate, so they usually see none.
- **Runtime context.** For baseline, implementer and tester agents the hook also injects the child's port range (`PORT` / `OPENFLEET_PORT_BASE`), the copied local files (never to be committed or printed), what the baseline covers (baseline agent), and the protected baseline test files (implementer and tester).
- **Stops.** The hook matches the child by recorded agent id, or by the unique child with that role. It then records the agent id (if it was not recorded at start) and takes a diff snapshot.
